## Section 1: What is Cloud Computing?

### Lecture: Traditional IT Overview

**How websites work (client-server basics)**
- A client (web browser) requests a website from a server via a **network**.
- Both client and server have **IP addresses**, which let requests be routed to the right destination and responses routed back.
- **Analogy:** sending a letter — you (client) write data (the letter), the postal network (internet) routes it using the address, the server (recipient) replies using the return address on the envelope.

**What's inside a server**
- **CPU** — performs computations/calculations.
- **RAM (memory)** — very fast, temporary storage for quick retrieval of information.
  - *Analogy:* CPU + RAM together work like a **brain** (computation + short-term retention).
- **Storage** — longer-term storage of data (e.g., files).
- **Database** — data organized/formatted so it can be easily searched and queried.
- **Networking** — routers, switches, DNS servers, etc.

**Core networking terminology**
| Term | Function |
|---|---|
| Network | Cables, routers, and servers connected together |
| Router | Forwards data packets between networks and knows how to route them across the internet |
| Switch | Forwards packets to the correct client within a local network |

**Traditional IT model and its problems**
- Historically: companies started with a server at home/garage (e.g., Google started in a garage), then grew into a dedicated **data center** as demand increased.
- Problems with owning your own servers/data center:
  - Ongoing costs: rent, power supply, cooling, maintenance.
  - Slow to add/replace servers (must order and physically install hardware).
  - **Limited scaling** — 10x growth requires 10x more servers, which may exceed available time/space.
  - Requires a 24/7 team to monitor infrastructure.
  - Vulnerable to disasters (earthquake, power outage, fire) with no built-in redundancy.
- These limitations are the motivation for **externalizing IT to the cloud** (topic of the next lecture).

### Lecture: What is Cloud Computing?

**Definition**
> Cloud computing is the **on-demand delivery** of compute power, database storage, applications, and other IT resources, through a cloud service platform, via **pay-as-you-go pricing**.

- **On-demand**: get exactly the type and size of resource you need, whenever you need it — provisioned in seconds, not with days/hours of advance notice.
- **Pay-as-you-go**: you only pay for what you use, when you use it; no charge once you stop.
- AWS (Amazon Web Services) owns and maintains the network-connected hardware; the customer provisions and uses resources via a web interface/application.

**Everyday examples of cloud services (used often without realizing it)**
- **Gmail** — cloud email service; you pay only for storage used.
- **Dropbox / Google Drive / Google Photos / iCloud** — cloud storage services. *(Fun fact: Dropbox was originally built on AWS.)*
- **Netflix** — built entirely on AWS; provides video-on-demand as a cloud service.

**Types of cloud**
| Type | Description | Example Provider(s) |
|---|---|---|
| **Private cloud** | Used by a single organization, not exposed to the public; more control and security for sensitive workloads | Rackspace *(out of scope for this course, but good to know)* |
| **Public cloud** | Resources owned/operated by a third-party provider, delivered over the internet | AWS, Microsoft Azure, Google Cloud |
| **Hybrid cloud** | Mix of private + public — keep some servers on-premises, extend some capability into the cloud | — |

> **Exam Tip:** Hybrid cloud is called out as important for the exam — know that it combines control over sensitive assets (on-prem) with the flexibility and cost-effectiveness of the public cloud.

**Five characteristics of cloud computing**
1. **On-demand self-service** — provision resources without AWS staff intervention.
2. **Broad network access** — resources accessible over the network in diverse ways.
3. **Multi-tenancy & resource pooling** — multiple customers share the same physical infrastructure/applications while keeping security and privacy.
4. **Rapid elasticity & scalability** — quickly acquire/dispose of resources; scale automatically with demand.
5. **Measured service** — usage is measured; you pay exactly for what you use.

**Six advantages of cloud computing**
1. **Trade CAPEX for OPEX** — no upfront hardware purchase; pay on demand, lowering Total Cost of Ownership (TCO).
2. **Economies of scale** — prices drop over time because AWS operates at massive scale/efficiency across all customers.
3. **Stop guessing capacity** — scale based on actual, measured usage instead of forecasting and pre-purchasing hardware.
4. **Increased speed and agility** — resources available on demand with no procurement blockers.
5. **Stop spending on running/maintaining data centers.**
6. **Go global in minutes** — leverage AWS's worldwide infrastructure (e.g., a 5-person team can launch a global application in minutes).

**Net result:** the cloud makes applications more flexible, cost-effective, scalable, elastic (scale out/in), highly available & fault tolerant (many data centers instead of one), and more agile (rapid develop/test/launch).

### Lecture: The Different Types of Cloud Computing

**Three cloud service (delivery) models**

| Model | What it provides | You manage | Provider manages |
|---|---|---|---|
| **IaaS** (Infrastructure as a Service) | Raw building blocks: networking, compute, storage | Applications, Data, Runtime, Middleware, OS | Virtualization, Servers, Storage, Networking |
| **PaaS** (Platform as a Service) | Removes need to manage underlying infrastructure; focus on deploying/managing apps | Applications, Data | Runtime, Middleware, OS, Virtualization, Servers, Storage, Networking |
| **SaaS** (Software as a Service) | A complete, ready-to-use product | Nothing (just use the product) | Everything |

- *Analogy:* IaaS gives you building blocks like **LEGOs** — high flexibility, and a natural stepping stone for migrating from on-premises IT to the cloud.
- **On-premises** (for comparison): you manage everything — applications, data, runtime, middleware, OS, virtualization, servers, storage, and networking.

**Real-world examples by model**
| Model | AWS example | Other examples |
|---|---|---|
| IaaS | Amazon EC2 | Google Cloud, Azure, Rackspace, Digital Ocean, Linode |
| PaaS | AWS Elastic Beanstalk | Heroku, Google App Engine, Windows Azure |
| SaaS | Many AWS services (e.g., Rekognition for machine learning) | Gmail, Dropbox, Zoom |

**AWS pricing fundamentals (pay-as-you-go)**
| Resource | You pay for |
|---|---|
| Compute | Exact compute time used |
| Storage | Exact amount of data stored |
| Networking | Only when data **leaves** the cloud (data transfer out); data going **into** the cloud is free |

This model solves the "expensive traditional IT" problem — you pay only for exactly what you need, generating significant cost savings.

### Lecture: AWS Cloud Overview

**History of AWS**
- Launched **internally** in 2002 at amazon.com after Amazon realized its own IT infrastructure could be externalized/offered to others.
- First **public** offering: **SQS** in 2004.
- **2006**: expanded with SQS, **S3**, and **EC2**.
- Later expanded globally beyond the US (e.g., into Europe).
- Well-known companies running on AWS: Dropbox, Netflix, Airbnb, NASA.

**AWS market position**
- Named a leader in Gartner's Magic Quadrant for many consecutive years.
- ~$90 billion in revenue as of 2023.
- ~31% market share in Q1 2024 (Microsoft Azure second at ~25%).
- Market leader for 13 consecutive years; over 1 million active users.

**What you can build on AWS**
- Applies across virtually every industry (e.g., Netflix, McDonald's, 21st Century Fox, Activision).
- Common use cases: migrating enterprise IT, backup & storage, big data analytics, website hosting, mobile/social app backends, gaming servers.

**AWS Global Infrastructure — core components**
- Regions, Availability Zones, Data Centers, Edge Locations, Points of Presence.

**Regions**
- A region is a **cluster of data centers** in a geographic area (e.g., Ohio, Singapore, Sydney, Tokyo).
- Identified by a name/code (e.g., `us-east-1`, `eu-west-3`).
- Most AWS services are **region-scoped** — using a service in one region is independent of using it in another (like starting fresh).

> **Exam Tip:** Know the four factors for choosing an AWS region:
> 1. **Compliance** — data sovereignty/legal requirements may require data to stay in a specific country (e.g., data in France may need to stay in France).
> 2. **Latency** — deploy close to your users to minimize lag.
> 3. **Service availability** — not all services are available in all regions.
> 4. **Pricing** — pricing varies by region.

**Availability Zones (AZs)**
- Each region contains multiple AZs — **usually 3**, minimum 3, maximum 6.
- Example: Sydney region (`ap-southeast-2`) has 3 AZs: `ap-southeast-2a`, `ap-southeast-2b`, `ap-southeast-2c`.
- Each AZ = one or more **discrete data centers** with redundant power, networking, and connectivity.
- AZs are **isolated from disasters** — a failure in one AZ is designed not to cascade to others.
- AZs within a region are linked via high-bandwidth, ultra-low-latency networking.

**Points of Presence / Edge Locations**
- AWS has **400+ points of presence** across **90 cities** in **40 countries**.
- Used to deliver content to end users with the lowest possible latency (covered in more detail later in the course, in the global infrastructure section).

**Global vs. Regional services**
| Global services (no region selection needed) | Regional services (scoped to a chosen region) |
|---|---|
| IAM, Route 53, CloudFront, WAF | EC2, Elastic Beanstalk, Lambda, Rekognition |

- AWS provides a **regional services table** (via the AWS Global Infrastructure site) showing which services are available in which region.

### Lecture: Tour of the Console & Services in AWS

- **Region selector** (top-right corner of the console): choose a region **geographically close to you** for the lowest latency; keep the same region throughout the course for consistency.
- **Console home page** shows: recently visited services, account health issues, cost and usage info, and solution-building tutorials.
- **Finding services**, two methods:
  1. **Services menu** (top-left) — browse **alphabetically** or **by category** (e.g., Compute).
  2. **Search bar** — search by service name (e.g., "Route 53") to get matching services, features, blog posts, knowledge articles, and documentation.
- **Global vs. regional view example**:
  - **Route 53** console shows **"Global"** in the top-right corner — no region selection required.
  - **EC2** console shows the currently selected region (e.g., "Ireland") — resources/view differ by region.
- The **AWS Global Infrastructure** website (searchable via Google) includes a **regional services table** to check whether a given service is available in your chosen region — useful if a service used in the course isn't available where you're working.

### Lecture: Shared Responsibility Model & AWS Acceptable Policy

**Shared Responsibility Model**
- Defines what is the **customer's** responsibility vs. **AWS's** responsibility.

| Responsibility | Owner | Covers |
|---|---|---|
| **Security *in* the cloud** | Customer | How you use and configure your resources — security, data, operating system, network & firewall configuration, etc. |
| **Security *of* the cloud** | AWS | Infrastructure, hardware, software, and AWS's own internal security |

> **Exam Tip:** The Certified Cloud Practitioner exam includes questions asking you to identify whether a given responsibility belongs to the customer or to AWS. This model/diagram is referenced repeatedly throughout the course.

**AWS Acceptable Use Policy**
- By using AWS, customers agree not to engage in:
  - Illegal, harmful, or offensive use or content.
  - Security violations.
  - Network abuse.
  - Email or other messaging abuse.

## Section 1 — Key Takeaways

**Most important concepts**
- Cloud computing = on-demand, pay-as-you-go delivery of compute, storage, database, and other IT resources — replacing the traditional model of owning and maintaining your own servers/data centers.
- Traditional IT's core problems (cost, slow scaling, maintenance burden, disaster risk) are exactly what the cloud's characteristics and advantages are designed to solve.
- Cloud deployment models: **private**, **public**, **hybrid**.
- Cloud service models: **IaaS**, **PaaS**, **SaaS** — differentiated by how much of the stack you manage vs. the provider manages.
- AWS's global infrastructure is built from **Regions** → **Availability Zones** → **Data Centers**, plus **Points of Presence/Edge Locations** for low-latency content delivery.
- The **Shared Responsibility Model** splits duties between customer ("security *in* the cloud") and AWS ("security *of* the cloud") — a recurring exam theme throughout the entire course.

**How the concepts relate**
- Traditional IT problems → motivate cloud computing → cloud is delivered via different **service models** (IaaS/PaaS/SaaS) and different **deployment models** (private/public/hybrid) → all built on top of AWS's physical **global infrastructure** (regions/AZs/edge locations) → governed by the **shared responsibility model** and AWS's **Acceptable Use Policy**.

**Key terminology to remember**
- On-demand, pay-as-you-go, CAPEX vs. OPEX, TCO
- Elasticity, scalability, multi-tenancy, resource pooling, measured service
- IaaS, PaaS, SaaS
- Private cloud, public cloud, hybrid cloud
- Region, Availability Zone (AZ), Data Center, Edge Location, Point of Presence
- Global service vs. Regional service
- Shared Responsibility Model: "security *in* the cloud" (customer) vs. "security *of* the cloud" (AWS)
- Acceptable Use Policy

**Key distinctions/comparisons**
- **On-premises vs. IaaS vs. PaaS vs. SaaS** — what you manage vs. what the provider manages (see table above).
- **Private vs. public vs. hybrid cloud** — ownership, exposure, and control trade-offs.
- **Global vs. regional AWS services** — e.g., IAM/Route 53/CloudFront/WAF (global) vs. EC2/Elastic Beanstalk/Lambda/Rekognition (regional).
- **Customer responsibility vs. AWS responsibility** under the Shared Responsibility Model.
- **Data transfer pricing**: into AWS = free; out of AWS = charged.

**You should be able to explain:**
- Why companies moved from traditional, self-managed IT/data centers to the cloud, and what specific problems the cloud solves.
- The formal definition of cloud computing and its five defining characteristics.
- The six advantages of cloud computing.
- The differences between private, public, and hybrid cloud, with real examples.
- The differences between IaaS, PaaS, and SaaS, including what's managed by the customer vs. the provider, with AWS and non-AWS examples.
- How AWS prices compute, storage, and networking/data transfer.
- The structure of AWS's global infrastructure: regions, availability zones, data centers, and points of presence/edge locations — and the four factors used to choose a region.
- The difference between a global AWS service and a regional AWS service, with examples of each.
- How to navigate the AWS Console (region selector, services menu, search bar) and check regional service availability.
- The Shared Responsibility Model — what falls under "security in the cloud" (customer) vs. "security of the cloud" (AWS) — and the basics of the AWS Acceptable Use Policy.
