## Section: EC2 - Elastic Compute Cloud

### Lecture: AWS Budget Setup

- Setting up a budget/alarm helps avoid unexpected charges while using AWS.
- Access billing via: top-right of console → **Billing and Cost Management**.
- **Important quirk**: IAM users — even with `AdministratorAccess` — get "Access Denied" on billing data by default. To fix this:
  - Log in as the **root** account → click account name → **Account** → scroll to **"IAM user and role access to billing information"** → activate IAM access.
  - This allows IAM admin users to view billing information going forward.
- **Billing console features**:
  - Month-to-date cost, forecasted cost for the current month, last month's total cost.
  - Cost breakdown by month.
  - **Bills** section: view "charges by service" for a specific month — e.g., a detailed breakdown of EC2 costs (NAT Gateway, EBS, Elastic IP, etc.) can be inspected here.
  - **Free Tier** page: shows current usage and forecasted usage against free tier limits; turns red if you're forecast to exceed the free tier.
- **Setting up a Budget**: left sidebar → **Budgets** → Create a budget using a simplified template:
  - **Zero spend budget** — sends an alert as soon as you spend $0.01.
  - **Monthly cost budget** — set a specific dollar threshold (e.g., $10/month) with configurable email alerts at multiple thresholds (e.g., 85% of actual spend, 100% of actual spend, 100% of forecasted spend).
- Even if you don't expect to spend money, setting a budget is good practice as a safety net against mistakes — and is described as a necessary skill when using AWS.

### Lecture: EC2 Basics

- **EC2 = Elastic Compute Cloud** — one of AWS's most widely used services; it is AWS's way of delivering **Infrastructure as a Service (IaaS)**.
- EC2 is not a single service — it's composed of several related components:
  - **EC2 Instances** — rentable virtual machines.
  - **EBS volumes** — virtual drives for data storage.
  - **Elastic Load Balancer (ELB)** — distributes traffic across machines.
  - **Auto Scaling Group (ASG)** — automatically scales services.
- **Configuration choices when renting an EC2 instance:**
  - Operating System: Linux (most popular), Windows, or macOS.
  - Compute power (number of CPU cores).
  - RAM (memory).
  - Storage: network-attached (EBS or EFS) or hardware-attached (EC2 Instance Store).
  - Networking: network card speed, public IP configuration.
  - Firewall rules: the **Security Group**.
  - Bootstrap script: **EC2 User Data**, which configures the instance at first launch.

**EC2 User Data / Bootstrapping**
- "Bootstrapping" means launching commands automatically when the machine first starts.
- The User Data script runs **only once** — at the instance's first boot, never again afterward.
- Typical uses: installing updates, installing software, downloading files from the internet, or any other setup task.
- > **Exam Tip:** EC2 User Data scripts run as the **root** user, so any command in the script has `sudo` rights.

### Lecture: Create an EC2 Instance with EC2 User Data to have a Website Hands On

**Launching an instance**: EC2 Console → Instances → Launch Instances. Key parameters:

| Setting | What was chosen / key notes |
|---|---|
| Name & Tags | Name tag: "My First Instance" |
| AMI (base image) | Amazon Linux 2 (a "Quick Start" AMI provided by AWS), free-tier eligible; custom AMIs can also be created |
| Instance Type | `t2.micro` — free-tier eligible, general purpose |
| Key Pair | Required for SSH; type **RSA**; format **.pem** for Mac/Linux/Windows 10+, **.ppk** for older Windows (7/8, used with PuTTY) |
| Network Settings | Instance gets a public IP; a Security Group is attached (auto-created as `launch-wizard-1` if none exists) |
| Security Group Rules (this demo) | Allow **SSH (port 22)** from anywhere; allow **HTTP (port 80)** from anywhere (needed for the web server) |
| Storage | Default root volume: 8 GB, `gp2` (general purpose SSD); free tier covers up to 30 GB of EBS storage |
| Delete on Termination | Enabled ("Yes") by default — the volume is deleted automatically when the instance is terminated |
| Advanced Details → User Data | A bootstrap script pasted here runs once at first launch — this demo's script updates the system, installs the HTTPD web server, and writes an HTML file, turning the instance into a simple "Hello World" web server |

- **Free tier**: 750 hours/month of `t2.micro` (or `t3.micro` if `t2.micro` isn't available in your region) for the first year, plus 30 GB of EBS storage.
- Launching is extremely fast — an instance goes from "pending" to "running" in roughly 10–15 seconds, illustrating the speed of the cloud.

**Instance details after launch**
- **Instance Name** and **Instance ID** (a unique identifier).
- **Public IPv4 address** — used to access the instance from outside.
- **Private IPv4 address** — used to access the instance internally, within the AWS network.
- Also shown: instance state, hostname, private DNS, instance type, AMI used, key pair used.
- **Security tab**: shows the attached security group (e.g., `launch-wizard-1`) and its inbound rules (port 22 open to everyone, port 80 open to everyone) plus the default outbound rule allowing all outbound traffic.

**Accessing the web server**
- Use the **public IPv4 address** with the **HTTP** protocol (not HTTPS) — e.g., `http://<public-ip>` — HTTPS will hang indefinitely since it isn't configured.
- The demo page displays "Hello World from <private IP>" — note this is the instance's **private** IP even though you accessed it via the **public** IP.

**Start / Stop / Terminate**
- **Stop Instance**: halts billing for compute while stopped; the attached volume (and its data) persists — you still pay for storage, but not for compute.
- **Terminate Instance**: permanently deletes the instance (and, by default, its root volume, due to "delete on termination").
- **Start Instance**: restarts a stopped instance.
- **Important:** stopping and then starting an instance can result in AWS assigning a **new public IPv4 address**. The **private IPv4 address always stays the same**, regardless of stop/start cycles.

### Lecture: EC2 Instance Types Basics

**Naming convention example: `m5.2xlarge`**
- **M** = instance class/family (e.g., general purpose).
- **5** = generation (increases as AWS improves the underlying hardware).
- **2xlarge** = size within that class (progression: small → large → 2xlarge → 4xlarge, etc.) — larger size means more CPU and memory.

**Instance type categories**

| Type | Best for | Example use cases | Example series names |
|---|---|---|---|
| **General Purpose** | Diverse workloads; good balance of compute, memory, networking | Web servers, code repositories | `t2.micro` (free tier), M series |
| **Compute Optimized** | Compute-intensive tasks | Batch processing, media transcoding, high-performance web servers, HPC (High Performance Computing), machine learning, dedicated gaming servers | C series (C5, C6, etc.) |
| **Memory Optimized** | Fast performance processing large datasets in memory (RAM) | In-memory relational/non-relational databases, distributed web-scale cache stores (e.g., ElastiCache), in-memory BI databases, real-time processing of big unstructured data | R series (R = RAM), X1, High Memory, Z1 |
| **Storage Optimized** | Workloads needing fast access to large local datasets | High-frequency OLTP systems, relational/NoSQL databases, in-memory caches (e.g., Redis), data warehousing, distributed file systems | I, D, or H1 series |

- This course primarily uses the free-tier-eligible `t2.micro` (General Purpose).
- **Example spec comparisons** given in the lecture:
  - `t2.micro`: 1 vCPU, 1 GB memory.
  - `r5.16xlarge`: 16 vCPU, 512 GB memory (memory-heavy).
  - `c5.4xlarge`: 16 vCPU, 32 GB memory (compute-heavy, comparatively less memory).
- **Reference tools:**
  - The official AWS EC2 instance types webpage — authoritative source for current types, specs, and pricing (this evolves over time).
  - **ec2instances.info** — a third-party site that compares all EC2 instance types side by side (On-Demand/Reserved cost, memory, vCPU count; sortable and searchable).

### Lecture: Security Groups & Classic Ports Overview

- **Security Groups** are firewalls that control traffic **into** and **out of** EC2 instances.
- Key characteristics:
  - Contain **only ALLOW rules** (no explicit deny rules).
  - Rules can reference **IP addresses** or **other security groups**.
  - Regulate traffic by **port**, **protocol** (e.g., TCP), and **authorized IP range** (IPv4 or IPv6).
  - Control both **inbound** (into the instance) and **outbound** (from the instance out) traffic.
- Rule fields: **Type**, **Protocol**, **Port Range**, **Source** — `0.0.0.0/0` means "anywhere" (any IP).
- **Default behavior**: all inbound traffic is **blocked** by default; all outbound traffic is **allowed** by default.

**Facts to know**
- A security group can be attached to **multiple instances** (not a 1:1 relationship).
- An instance can have **multiple security groups** attached.
- Security groups are locked to a specific **region/VPC combination** — must be recreated if you switch region or VPC.
- Security groups live **outside** the EC2 instance — if traffic is blocked, the instance never even receives it (unlike an in-application firewall).
- Best practice: maintain a **separate security group dedicated to SSH access**.

**Troubleshooting tip**
| Symptom | Likely cause |
|---|---|
| Connection **times out** | Security group is blocking traffic |
| Connection **refused** | Security group allowed the traffic through, but the application itself isn't running or is erroring |

**Advanced feature — referencing security groups**
- A security group's inbound rule can authorize traffic from **another security group** rather than an IP range.
- Example: SG1's inbound rule allows traffic from SG2 → any instance with SG2 attached can reach any instance with SG1 attached, regardless of IP address. Useful pattern for load balancer setups.

> **Exam Tip — classic ports to memorize:**

| Port | Use |
|---|---|
| 21 | FTP (File Transfer Protocol) — upload files to a file share |
| 22 | SSH (Secure Shell) — log into a **Linux** EC2 instance |
| 22 | SFTP (Secure File Transfer Protocol) — securely upload files, via SSH |
| 80 | HTTP — access unsecured websites |
| 443 | HTTPS — access secured websites (the modern standard) |
| 3389 | RDP (Remote Desktop Protocol) — log into a **Windows** instance |

### Lecture: Security Groups Hands On

- Access via: EC2 Console → Networking & Security → **Security Groups**.
- Default groups seen: **"default"** (created automatically) and **"launch-wizard-1"** (auto-created when the first instance was launched).
- Each security group has a unique **ID**.
- **Demonstration**: removing the HTTP (port 80) inbound rule immediately blocks web access — refreshing the web page results in an infinite loading screen (a **timeout**).
  - > **Exam Tip:** a timeout when connecting to an EC2 instance (SSH, HTTP, or otherwise) is almost always caused by a **security group** issue — check the rules first.
- Re-adding the HTTP rule (port 80, source `0.0.0.0/0` for IPv4) restores access immediately.
- You can define custom port ranges/protocols; selecting a protocol from the dropdown (e.g., HTTPS) auto-fills the standard port (443).
- **Source options**: a custom CIDR block (e.g., "anywhere"), **"My IP"** (restricts access to just your current IP — caution: if your IP changes later, you'll get a timeout), or referencing another security group / a prefix list.
- **Outbound rules example**: allow all IPv4 traffic to anywhere — gives the instance full internet connectivity.
- Confirmed again: an EC2 instance can have **multiple security groups attached** (rules from all attached groups are additive), and a single security group can be attached to **multiple different EC2 instances**.

### Lecture: SSH Overview

**Connection method depends on your OS:**

| Your OS | Method |
|---|---|
| Mac / Linux / Windows 10+ | Built-in SSH command-line utility |
| Windows before version 10 (7/8) | **PuTTY** (free tool, does the same job as SSH) |
| Any OS (Mac, Linux, all Windows versions) | **EC2 Instance Connect** — browser-based, no terminal or key management needed, but currently only works with **Amazon Linux 2** |

- The course primarily uses **EC2 Instance Connect** going forward since it's the simplest option and requires no local setup.

- You only need **one** working connection method (terminal SSH, PuTTY, or EC2 Instance Connect) — not all of them.

### Lecture: How to SSH using Linux or Mac

- SSH lets you control a remote server via terminal/command line.
- Requirements: the EC2 instance's **public IP**, and a security group with **port 22 (SSH)** open.

**Steps**
1. Locate your downloaded `.pem` key file (make sure there are no spaces in the filename or path).
2. Navigate your terminal to the directory containing the `.pem` file (using `cd`, `ls`, `pwd` to verify location).
3. Run: `ssh -i EC2Tutorial.pem ec2-user@<public-ip>` — `ec2-user` is the default pre-configured username on the Amazon Linux 2 AMI.
4. **"Too many authentication failures"** error → usually means the key file wasn't specified with `-i`.
5. **"Unprotected key file"** error → fix permissions with: `chmod 0400 EC2Tutorial.pem`.
6. Accept the host authenticity prompt ("yes") if shown.
- Once connected, you can run Linux commands directly (e.g., `whoami`, `ping google.com`).
- To exit: type `exit` (or Ctrl+C/Ctrl+D as applicable).
- Reminder: if the instance is stopped and restarted, the public IP may change — you'll need the new IP for future SSH sessions.

---

### Lecture: How to SSH using Windows

*(Applies to Windows 7/8, or as an alternative on any Windows version)*

- Use **PuTTY**, a free SSH client.

**Steps**
1. Download and install PuTTY (includes the PuTTY app and **PuTTYgen**).
2. If you don't already have a `.ppk` key file, use **PuTTYgen** to convert your `.pem` file: load the `.pem` file, then "Save private key" as `.ppk`.
3. In the PuTTY app: enter `ec2-user@<public-ip>` as the hostname, set connection type to SSH, and save the session profile (e.g., named "EC2 Instance").
4. Under **SSH → Auth**, browse to and select the `.ppk` private key file, then save the profile again.
5. Click **Open** to connect; accept the "host not trusted" prompt if shown.
- Once connected, you can run Linux commands (e.g., `whoami`, `ping google.com`).
- Saved PuTTY session profiles allow quick reconnection later without repeating all setup steps.

---

### Lecture: How to SSH using Windows 10

- Windows 10+ includes a **built-in SSH command**, usable from PowerShell or Command Prompt.

**Steps**
1. Navigate to the directory containing your `.pem` file (`cd`, `ls`).
2. Run: `ssh -i EC2Tutorial.pem ec2-user@<public-ip>`.
3. Accept the host authenticity prompt if shown.

**Fixing a key file permission issue** (via File Properties → Security → Advanced):
- Ensure you are the **Owner** of the key file.
- Remove other entities (e.g., SYSTEM, Administrators) from having access.
- **Disable inheritance** and grant yourself **Full Control** only.
- Once fixed, the SSH command works without further permission prompts.
- The SSH command also works from Command Prompt, not just PowerShell.
- To exit: type `exit` or use Ctrl+D.

### Lecture: EC2 Instance Connect

- **EC2 Instance Connect** is a browser-based alternative to traditional SSH/PuTTY.
- Access: select the instance → **Connect** → **EC2 Instance Connect** tab.
- No SSH key management required — AWS automatically uploads a **temporary SSH key** to establish the connection.
- The username field is pre-filled with `ec2-user` (assumes an Amazon Linux 2 instance).
- Connecting opens a new browser tab with a terminal session where you can run Linux commands (e.g., `whoami`, `ping google.com`).
- **Important:** EC2 Instance Connect relies on SSH under the hood — it still requires **port 22 (SSH)** to be open in the instance's security group (sometimes for both IPv4 and IPv6 sources), or the connection will fail.

### Lecture: EC2 Instance Roles Demo

- Demonstrates why and how to use **IAM Roles** with EC2 instances instead of hardcoding credentials.
- Connecting to the instance and running `aws iam list-users` initially fails with an "unable to locate credentials" error (since the AWS CLI comes pre-installed on the Amazon Linux AMI, but isn't configured).
- **Critical security rule:** **Never** run `aws configure` and enter your personal IAM Access Key ID / Secret Access Key on an EC2 instance — anyone else with access to that instance (e.g., via EC2 Instance Connect) could retrieve and misuse those credentials.
- **Correct approach:** attach an **IAM Role** to the EC2 instance instead:
  - Instance → **Actions → Security → Modify IAM role** → select a previously created role (e.g., "DemoRoleForEC2" with the `IAMReadOnlyAccess` policy attached) → Save.
  - Once attached, commands like `aws iam list-users` succeed — with no `aws configure` step ever needed.
- Detaching the policy from the role (or the role from the instance) causes subsequent API calls to fail with "access denied" — permission changes may take a short time to propagate before taking effect.
- **Key takeaway:** IAM Roles are the correct, secure mechanism for providing AWS credentials/permissions to EC2 instances.

### Lecture: EC2 Instance Purchasing Options

> **Exam Tip:** Expect questions asking you to match a workload description to the correct purchasing option.

| Purchasing Option | Discount vs. On-Demand | Term / Commitment | Best For | Key Notes |
|---|---|---|---|---|
| **On-Demand** | None (highest cost) | None | Short-term, unpredictable, uninterrupted workloads | Billed per second (Linux/Windows, after the first minute) or per hour (other OSes); no upfront payment, no long-term commitment |
| **Reserved Instances (Standard)** | Up to ~72% | 1 or 3 years | Steady-state usage (e.g., databases) | Reserve specific attributes (instance type, region, tenancy, OS); pay all/partial/no upfront (more upfront = bigger discount); can be bought/sold on the Reserved Instance Marketplace |
| **Convertible Reserved Instances** | Up to ~66% | 1 or 3 years | Steady-state usage that also needs flexibility | Can change instance type/family, OS, scope, and tenancy during the term; slightly lower discount than Standard due to the added flexibility |
| **Savings Plans** | Up to ~72% | 1 or 3 years | Long-term workloads with flexible instance needs | Commit to a $-per-hour spend rather than a specific instance; locked to an instance family + region, but flexible on instance size, OS, and tenancy; usage beyond the committed amount is billed at the on-demand rate |
| **Spot Instances** | Up to ~90% | None — can be reclaimed at any time | Short, resilient, interruption-tolerant workloads (batch jobs, data analysis, image processing, distributed workloads) | The cheapest option; you set a max price you're willing to pay; the instance can be reclaimed if the spot price exceeds your max; **not** suited for critical jobs or databases |
| **Dedicated Hosts** | Can reach up to ~70% w/ reservation | On-demand or 1/3-year reservation | Compliance requirements; bring-your-own-license (BYOL) software billed per-socket/core/VM | An entire physical server dedicated to you; the most expensive option; gives full visibility/control over the physical server and instance placement |
| **Dedicated Instances** | On-demand pricing | — | Similar needs to Dedicated Hosts, without needing full server control | Runs on hardware dedicated to your account, but you may share that hardware with other instances in your own account; **no control over instance placement** (this is the key distinction vs. Dedicated Hosts) |
| **Capacity Reservations** | None — billed at on-demand rate regardless of use | Any duration, no commitment | Short-term, uninterrupted workloads needing guaranteed capacity in a specific AZ | Reserves capacity (not a discount); can be combined with Reserved Instances/Savings Plans for a discount; billed at the on-demand rate whether or not you actually launch instances; can be canceled at any time |

**Analogy used in the lecture (resort booking):**
- **On-Demand** = walk-in and pay full price whenever you like.
- **Reserved** = book far in advance for a long stay and get a discount.
- **Savings Plan** = commit to spending a set amount per month, with flexibility on room type.
- **Spot** = last-minute, deeply discounted rooms — but you can be bumped if someone bids higher.
- **Dedicated Host** = book an entire building/resort for yourself.
- **Capacity Reservation** = book a room you may not use, but it's guaranteed if you do — and you pay full price either way.

## Section: EC2 - Elastic Compute Cloud — Key Takeaways

**Most important concepts**
- EC2 (Elastic Compute Cloud) is AWS's core Infrastructure as a Service (IaaS) offering — rentable virtual machines ("instances") plus related components (EBS, ELB, ASG).
- Launching an instance requires choosing: an **AMI** (OS image), an **instance type** (CPU/memory/cost profile), a **key pair** (for SSH), **network settings** including a **Security Group** (firewall), **storage**, and optionally an **EC2 User Data** bootstrap script.
- **Security Groups** are stateless-feeling, allow-only firewalls that sit outside the instance and control inbound/outbound traffic by port, protocol, and IP/security-group source.
- Connecting to an instance can be done via **SSH** (terminal, on Mac/Linux/Windows10+), **PuTTY** (older Windows), or **EC2 Instance Connect** (browser-based, no key management, Amazon Linux 2 only) — all three ultimately depend on port 22 being open.
- **IAM Roles**, not hardcoded access keys, are the correct way to grant an EC2 instance permission to call other AWS services.
- AWS offers multiple **purchasing options** (On-Demand, Reserved, Savings Plans, Spot, Dedicated Host/Instance, Capacity Reservations) trading off cost, flexibility, and reliability.
- The **Shared Responsibility Model** for EC2: AWS secures the underlying infrastructure/hardware; the customer secures the guest OS, software, security group configuration, IAM roles, and data.

**How the concepts relate**
- An **instance type** determines available CPU/memory/network resources; **instance purchasing options** determine how you pay for that capacity based on your workload's predictability and flexibility.
- A **Security Group** governs whether a connection method (SSH, HTTP, RDP, etc.) can even reach the instance — a misconfigured security group is the most common cause of connection **timeouts**, regardless of which access method (SSH, PuTTY, EC2 Instance Connect, or a web browser) is used.
- **EC2 User Data** configures the instance's software at first boot (e.g., installing a web server), while an **IAM Role** attached to the instance governs what AWS API calls the instance itself is allowed to make afterward — these are two separate mechanisms (one for OS-level setup, one for AWS permissions).
- **Stopping vs. terminating** an instance affects billing and data persistence differently, and stopping/starting can change the **public IP** (but never the **private IP**) — relevant both for hands-on work and cost management (tracked via **AWS Budgets**).

**Key terminology to remember**
- EC2, AMI (Amazon Machine Image), instance type/class/generation/size (e.g., `t2.micro`, `m5.2xlarge`)
- General Purpose, Compute Optimized, Memory Optimized, Storage Optimized instance families
- Security Group, inbound/outbound rules, `0.0.0.0/0`
- Key Pair (`.pem` / `.ppk`), SSH, PuTTY, EC2 Instance Connect
- EC2 User Data, bootstrapping
- Public IPv4 vs. Private IPv4
- IAM Role (for EC2/AWS services) vs. IAM Role for people
- On-Demand, Reserved Instances (Standard/Convertible), Savings Plans, Spot Instances, Dedicated Host, Dedicated Instance, Capacity Reservation
- Delete on Termination, EBS volume
- AWS Budgets, Free Tier

**Key distinctions/comparisons**
- **Timeout vs. Connection Refused**: security group issue vs. application-level issue.
- **Public IP vs. Private IP**: public IP can change on stop/start; private IP never changes.
- **Stop vs. Terminate**: stop preserves the instance/volume (storage cost only); terminate deletes the instance (and, by default, its root volume).
- **Dedicated Host vs. Dedicated Instance**: full physical server control and visibility vs. dedicated-but-shared-within-your-account hardware with no control over instance placement.
- **Reserved Instances vs. Savings Plans**: committing to a specific instance configuration vs. committing to a dollar amount of usage with more flexibility.
- **General Purpose vs. Compute Optimized vs. Memory Optimized vs. Storage Optimized** instance families and their respective use cases.
- **Customer responsibility vs. AWS responsibility** under the EC2 Shared Responsibility Model.

**You should be able to explain:**
- What EC2 is, what it's composed of, and the key parameters chosen when launching an instance.
- The instance type naming convention and the four main instance family categories with example use cases.
- How Security Groups work: default allow/deny behavior, inbound vs. outbound rules, and how to diagnose a timeout vs. a connection-refused error.
- The classic ports to know for the exam (21, 22, 80, 443, 3389) and what each is used for.
- The three ways to connect to an EC2 instance (SSH, PuTTY, EC2 Instance Connect) and their OS/AMI requirements.
- Why you should never hardcode AWS credentials on an EC2 instance, and how IAM Roles solve that problem.
- The differences between all EC2 purchasing options and which workload type each is best suited for.
- The Shared Responsibility Model as applied specifically to EC2.
- How to set up AWS Budgets and use the Free Tier dashboard/Bills page to monitor and control costs.
